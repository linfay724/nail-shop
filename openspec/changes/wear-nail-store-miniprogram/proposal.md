# Proposal

## Why

当前仓库只有一个 uni-app 默认脚手架页面，没有任何业务能力。需要把它变成一个可出售穿戴甲（成品甲片）的微信小程序，让顾客能完成「看货 → 加购 → 下单 → 收货」的闭环；同时店主需要一个仅自己可见的空间，记录每款美甲的甲片型号、色号、饰品用量与分步制作工艺——这些是商业机密，一旦随普通用户接口下发就等于泄题。

本变更只规划小程序端（页面、交互、数据层与接口契约），服务端另行立项；因此所有接口按契约先行、由本地 mock 层实现，后续替换真实服务端时页面逻辑不变。

补充前提：这是一家实际经营的小店，商品量级预计上千款，店内不只店主一人（美甲师参与制作），且同一套小程序可能需要服务多个经营主体。因此规格必须是「尺码 × 甲型」的组合矩阵而非单一选项，账号必须区分角色，管理入口必须按人发码并按主体隔离数据；同时成品甲按「副」（通常 10/12 片）计价而非按件，物流只走快递，售后只走人工协商——这些都会改变数据模型与页面行为，必须在 MVP 一次做对。

但仓库目前仍是 `uni-preset-vue` 生成的 JS 空壳：没有 TypeScript、状态管理、UI 组件库，`vite.config.js` 只有默认配置，`package.json` 还挂着 10 余个用不到的平台包。直接在其上写 20 多个页面，类型错误只能在运行时暴露，跨页状态与视觉规范也会各自为政。因此本变更把「工程基线升级」与「业务实现」合并为一次交付：先锁定 TypeScript + Pinia + uView Pro 基线，再在其上写业务。

## What Changes

- 工程基线升级：`vite.config.js` → `vite.config.ts`（`@` 别名、按 mode 加载环境变量），`src/main.js` → `src/main.ts`，全量 TypeScript strict 且 `type-check` 为门槛；引入 Pinia 2.1.7 与统一持久化插件、uView Pro 0.6.23（easycom + 主题覆盖）；`package.json` 只保留 H5 与微信小程序脚本并移除多余平台包。
- 搭建小程序骨架：`pages.json` 配置 4 个 tabBar 页面（首页 / 分类 / 购物车 / 我的，与原型 v1.1 一致）与主包页面，订单入口收敛至个人中心；`pages-admin` 管理端分包（不进 tabBar）。
- 用户端页面：首页（品牌区 + hero 轮播 + 推荐商品位 + 服务说明，不含搜索框与分类入口）、商品列表（「分类」tab：顶部搜索 + 综合/销量/上新/价格排序、名称/标签搜索、分页、封面/名称/售价/销量）、商品详情（图片轮播 + 1 个视频、尺码 × 甲型规格选择、副与片数说明、工具包可选文案、收藏、评价列表）、购物车（多规格行、配件行、数量增减、选中结算、包邮进度提示）、结算下单（地址、运费、定制备注、支付）、订单列表与详情（状态流转、物流、确认收货、售后协商、发表评价）、售后协商页（问题类型/描述/凭证意向表单，提交后跳转客服会话）、个人中心（微信授权登录、订单/收藏/地址/尺码指引/客服/协议入口与管理端说明占位卡）、地址管理与编辑、尺码测量指引页、用户协议与隐私政策页。
- 管理端分包页面：扫码入口页 + 身份与角色校验、按角色呈现的工作台（顶部展示在售商品 / 待发货 / 待处理售后三项计数）、商品管理列表与编辑（基础展示信息、尺码 × 甲型规格库存与价格差、上下架）、制作档案（店主可写；美甲师只读材料与步骤）、订单管理（筛选含「售后」、详情、定制备注、列表卡片内联填单号发货）、评价管理 / 运费规则配置（两个工作台入口进入同一「评价与规则」页）、账号管理（查看账号、发码/停用/重新生成码；账号由服务端预置，不提供新增与角色分配）。
- 数据层与契约：统一 `request` 封装 + 本地 mock 适配层（内存 + 本地缓存持久化），为每个接口定义请求/响应字段与可见性等级（公开 / 美甲师 / 店主）；普通用户视图只投影公开字段，制作字段仅在管理端契约中出现，成本字段仅在店主契约中出现。
- 权限落地：`admin` 分包按角色守卫（缺权限重定向工作台并提示）、`pages-admin` 之外不渲染管理入口、管理端页面不引用用户端组件或公共 mutable 状态；写接口在数据层再做一次角色校验。
- 商品规格模型：一个商品持有「尺码 × 甲型」的组合矩阵，每个组合独立库存与可选价格差；尺码枚举为 S / M / L / 其他，甲型枚举为短圆 / 中长 / 长梯 / 其他；选择「其他」时下单页出现定制备注输入框并必填校验；商品单位为「副」，详情页说明每副片数（10 或 12 片）；工具包作为独立配件商品售卖（详情页仅文案提示，不参与副数统计）。
- 内容与素材：商品详情支持图片轮播 + 1 个视频；制作步骤每步支持多图 + 短视频并保持可排序；用户评价先发先显，管理员可删除或隐藏，评价支持图片或视频；收藏改为服务端同步（换设备可见）。
- 交易与运费：纯快递发货；售后提供「售后协商」意向页（问题类型、描述、凭证上传），提交后跳转客服会话并生成协商记录，处理仍在线下完成，不做线上退款/退货流程；满 2 副包邮，未满按店主配置的固定邮费收取，阈值与固定邮费均由店主在管理端配置。
- 多账号与角色权限：支持店主（owner）与美甲师（artist）两种角色；美甲师只读材料清单与制作步骤，不可改价、上下架、处理订单或管理账号；店主拥有全部管理权限，含发码、停用账号与重新生成入口码，但管理端不提供新增账号与角色分配（账号由服务端预置）；权限同时做前端路由拦截与后端字段级/接口级校验。
- 管理端入口：改为扫码进入（不进入 tabBar，也不再依赖口令），一人一码绑定唯一管理账号；扫码后校验身份与角色，账号停用后其码立即失效；服务多方主体时数据按主体隔离，入口码与主体绑定。
- 搜索与商品量级：面向上千款商品，支持按商品名称与标签搜索，列表分页加载；MVP 不做拼音/分词高级搜索，也不做批量商品导入。
- 页面补充：尺码测量指引（静态图文）、用户协议与隐私政策占位框架页。
- 明确不做：材料库存管理与低库存提醒、数据看板（工作台仅展示在售商品 / 待发货 / 待处理售后三项简单计数，不做图表）、优惠券/满减、线上退款/退货流程（仅保留售后协商意向记录与线下人工处理）、定制报价表单（定制仅通过「其他」选项 + 下单定制备注表达）、批量商品导入、评价审核后台、分享海报生成、真实微信支付商户对接（支付结果由 mock 模拟）。

## Capabilities

### New Capabilities
- `product-catalog`: 首页轮播与推荐位（不含搜索/分类入口）、商品列表排序与名称/标签搜索分页、商品详情（多图 + 视频）、尺码 × 甲型规格矩阵与「其他」定制、按副计价与片数说明、工具包独立配件商品、公开的尺码测量指引（个人中心进入）。
- `shopping-cart`: 多规格（尺码 × 甲型）购物车行的增删改、配件行、选中状态与结算金额计算。
- `customer-orders`: 下单支付（含地址与「其他」定制备注）、运费计算与包邮规则、订单状态流转、物流查看、确认收货、售后协商意向页与客服协商记录（不做线上退款/退货）。
- `user-account`: 微信授权登录与会话、个人中心聚合入口、服务端同步收藏、收货地址管理、客服入口。
- `admin-console`: 扫码入口与身份校验、前端路由守卫、工作台三项计数、按角色的管理端商品/订单（含「售后」筛选与内联发货）/评价与规则（合并页）/账号管理、主体内数据隔离。
- `craft-archive`: 制作档案的材料清单、分步图文与短视频、排序与成本核算；店主可读写，美甲师只读且看不到成本。
- `data-visibility`: 公开 / 美甲师 / 店主三级字段可见性与接口级权限校验，确保普通用户链路绝不出现档案与成本字段。
- `account-roles`: 店主与美甲师两种角色、权限矩阵、一人一码的发放与停用、入口码与主体绑定。
- `customer-reviews`: 已完成订单发表评价（图/视频）、先发先显、管理员隐藏或删除。
- `legal-pages`: 用户协议与隐私政策的占位框架页及其入口。

## Impact

- 配置：`vite.config.ts`、`tsconfig.json`、`tsconfig.node.json`、`.env.development`、`.env.production`、`src/pages.json`（easycom、tabBar、主包/分包路由、新增搜索/协议/政策/评价/账号管理页）、`src/manifest.json`（小程序 appid 与应用信息）、`src/uni.scss`（设计 token 与 uView Pro 主题覆盖）。
- 新增代码：`src/main.ts`、`src/types/**`、`src/stores/**`（Pinia setup store：登录态、购物车、员工会话与角色）、`src/config/**`、`src/pages/**`（用户端页面）、`src/pages-admin/**`（管理端分包，新增评价管理、运费配置、账号管理）、`src/api/**`（TS 契约与请求封装，新增 `reviewApi`、`staffApi`、`shippingApi`）、`src/mock/**`（mock 数据与适配层，新增账号/入口码/评价/运费配置表）、`src/components/**`（仅业务特有组件，通用交互复用 uView Pro）、`src/utils/**`（价格、路由与角色守卫、存储、扫码解析）。
- 数据模型：商品 SKU 改为 `size(enum) × shape(enum)` 组合矩阵（`stock` + `priceDiff`）；商品增加 `unit`、`piecesPerSet`、`tags[]`、`video`；制作档案增加步骤 `title` 与 `video`，成本改为 `cost{materialCost, hours, suggestedPrice}`；订单增加 `shippingFee` 与 `customNote`（移除普通订单备注 `remark`）；新增 `StaffAccount`、`QrCode`、`Review`、`ShippingConfig`、`AfterSaleRequest`（售后协商意向记录）契约。
- 依赖：新增 `uview-pro@0.6.23`、`pinia@2.1.7`、`typescript`、`vue-tsc`、`@vue/tsconfig`、`@types/node`、`sass@1.63.2`；移除 `@dcloudio` 中非 H5/微信小程序的平台包；Vue 保持 `3.4.21` 与编译器配套。
- 构建目标：仅 H5 与微信小程序，脚本收敛为 `dev:h5`、`build:h5`、`dev:mp-weixin`、`build:mp-weixin`、`type-check`。
- 外部系统：微信登录、支付、扫码取参（`scene`）与上传接口按契约占位；小程序码生成与主体鉴权延后到服务端立项阶段，mock 以入口码字符串模拟。
- 需移除/改写的既有实现：管理端口令鉴权（改为扫码 + 一人一码）、线上售后申请页与管理员退款/拒绝流程（改为售后协商意向页 + 客服协商记录）、商品单值「甲型 + 甲片数量」规格（改为尺码 × 甲型矩阵）、本地收藏（改为服务端同步）。
